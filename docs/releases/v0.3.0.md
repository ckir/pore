# pore v0.3.0

Released 2026-09-10. Published at
<https://github.com/ckir/pore/releases/tag/v0.3.0> — this file is the source for that
release's notes.

## Upgrading — rebuild your index

The index schema changed in this release: file indexes now carry FAST fields, a `modified`
timestamp, an `ext` field, and stored text. Existing on-disk indexes predate all of that, so
run once after upgrading:

```bash
pore search --rebuild "your query" /path
```

Without it, sorting and aggregation have nothing to read.

## Two flags that never worked now do

`--sort` and `--aggregate` were both declared in `--help` and documented in the README while
being wired to nothing. Passing them changed no behaviour whatsoever. Both are now
implemented.

```bash
pore search "panic" --sort path      # or --sort date
pore search "todo" --aggregate ext
```

`--aggregate` groups the documents matching your query into buckets by a FAST field
(`ext`, `filepath`, `modified`) and prints the counts as JSON, so it composes with `--jq`:

```console
$ pore search "todo" --aggregate ext --jq '[.ext.buckets[].key]'
["rs", "md"]
```

Aggregating on a field that is missing or not a fast field now fails with an error naming
the field, rather than a generic one from inside the collector.

## Regex queries

Regex support existed only inside a test — every regex query through the CLI was rejected
with *"Regex queries are not allowed"*. It is now enabled on the parser.

```bash
pore search "contents:/w.lf/"        # matches the term "wolf"
pore search "filepath:/.*\.rs/"      # matches the whole path
```

Two limits are worth knowing, and both come from Tantivy rather than pore:

- **A regex must name a field.** A bare `/.../` is rejected — it needs a specific field.
- **On a tokenized field a regex matches a single term.** `contents:/w.lf/` finds `wolf`,
  but a pattern containing a space can never match, because no token contains one.
  `filepath` is stored whole, which is why path regexes work against the entire path.

The README's old examples used a field named `path`, which does not exist; the searchable
fields are `contents` and `filepath`.

## `--snippets`

New opt-in output mode returning Tantivy-generated snippets — a condensed extract with the
match highlighted — instead of full matching lines.

```bash
pore search "error" --snippets
```

**The JSON output contract is unchanged by default.** Results still carry `lines` with 1-based
`number` and `text`. `snippets` appears only under `--snippets`, and the two are mutually
exclusive, so existing `--jq` filters over `.lines` keep working.

## Windows: pore no longer requires `HOME`

`HOME` is not a standard Windows environment variable, and pore required it for both its
config file and its index cache. On a stock Windows box **every command that did real work
failed** with a bare `environment variable not found` — only `--help` and `--version`
survived. It hid during development because Git Bash sets `HOME`.

Both lookups now fall back to `%USERPROFILE%` after `HOME`, so the config lives at
`%USERPROFILE%\.config\pore.toml` unless `XDG_CONFIG_HOME` or `HOME` says otherwise. When
nothing resolves, the error names every variable it consulted instead of naming none.

## Other fixes

- **Errors no longer print a stray `<disabled>` line.** Every failure ended with that
  placeholder, because the backtrace was printed unconditionally and that is how it renders
  when capture is off. It is now printed only when actually captured, and readably —
  `RUST_BACKTRACE=1` gives a numbered multi-line trace instead of one long line.
- **The Lua module did not compile.** `pore-lua` failed to build in its real module
  configuration, so the shipped module was unloadable. Fixed, and CI now builds that
  configuration — no other build command compiles it.
- **Lua bindings reached parity with the CLI**: regex works through `search` and `aggregate`,
  and query errors report the underlying cause instead of a generic "Error parsing query".
- **Snippet highlighting honours `--color`.** It previously wrote raw ANSI escapes directly,
  which leaked colour into piped and redirected output, and let Tantivy's HTML markup and
  entities reach the terminal verbatim.
- **Indexing** now builds documents through a custom `Document` implementation rather than
  the `doc!` macro, avoiding a copy of each file's contents on the way into the index. No
  benchmark accompanies this, so treat it as a change to the indexing path rather than a
  measured speedup.

## Lua module

Now documented in the README, including the part that is easy to get wrong: the default
features build a cdylib with Lua linked in, which **is not loadable as a Lua module**. You
need `--no-default-features --features lua55,module`.

```lua
local pore = require("pore_lua")
local idx = pore.get_file_index("/path/to/project", "/path/to/cache", { language = "english" })
idx:update(false)
for _, hit in ipairs(idx:search("contents:/w.lf/", { limit = 10 })) do
  print(hit.file, hit.score)
end
```
